- Event loop blocking from synchronous `fs` methods (like `fs.existsSync` or `fs.writeFileSync`) in Node.js backend services can be optimized by replacing them with their asynchronous equivalents (`fs.promises.access`, `fs.promises.writeFile`). In high-concurrency environments, using a shared promise (`initPromise`) is an effective pattern to prevent race conditions during asynchronous initialization without duplicating operations.

## 2024-05-18 - Avoid Multiple Unmemoized Array Iterations for Derived Metrics
**Learning:** Found a common pattern in the React codebase (e.g., `AnalyticsPage.tsx`, `AdminDashboardPage.tsx`) where multiple `.filter().length` calls were used consecutively to derive aggregate metrics from a single state array during render. This resulted in O(N*M) operations (where M is the number of filters) running on every re-render, blocking the main thread for large datasets.
**Action:** Always replace chained/multiple `.filter()` or `.reduce()` calls that traverse the same array with a single-pass `for...of` loop wrapped in a `useMemo` hook. This converts the operation to O(N) and ensures the calculation only runs when the dependency array actually changes, significantly improving render performance.
