- Event loop blocking from synchronous `fs` methods (like `fs.existsSync` or `fs.writeFileSync`) in Node.js backend services can be optimized by replacing them with their asynchronous equivalents (`fs.promises.access`, `fs.promises.writeFile`). In high-concurrency environments, using a shared promise (`initPromise`) is an effective pattern to prevent race conditions during asynchronous initialization without duplicating operations.
## 2026-10-01 - Optimizing React Array Filtering with Single-Pass Memoization
**Learning:** Chaining or repeating multiple `.filter()` calls on large arrays inside a React component's render body causes severe O(N) performance penalties on every re-render, especially for datasets like `issues` where multiple derived lists are needed (e.g. `pending`, `inProgress`, `resolved`).
**Action:** Replace multiple sequential `.filter()` operations with a single-pass `for` loop, accumulating results into distinct collections, and wrap this logic within a `useMemo` hook to execute only when the source dependency changes. Always explicitly type the initial accumulator state (e.g., `[] as IssueReport[]`) to satisfy TypeScript.
