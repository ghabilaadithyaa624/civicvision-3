## 2024-05-24 - Proper Merging of ARIA Attributes and Props Spread in Input Components
**Learning:** When creating reusable input components that compute internal accessibility attributes (like `aria-describedby` for error text or `aria-invalid`), placing `{...rest}` *after* these attributes will allow parents to unintentionally override the internal bindings. Similarly, if a parent explicitly passes `aria-describedby` (e.g., to describe formatting requirements), the internal component must carefully merge the passed value with its internal IDs to preserve both accessibility links.
**Action:** Always spread `{...rest}` before explicit internal attributes on DOM elements. When applying ID-referencing ARIA attributes (like `aria-describedby` or `aria-labelledby`) internally, explicitly merge them with the corresponding `rest` prop (e.g., `[rest['aria-describedby'], errorId].filter(Boolean).join(" ") || undefined`).
