
## 2024-05-19 - Safe {...rest} Prop Spreading with Accessibility Attributes
**Learning:** When building reusable UI components (like InputField) that generate internal ARIA attributes (e.g., `aria-describedby` for error states, `aria-invalid`), placing `{...rest}` *after* these attributes can accidentally overwrite them if the parent passes conflicting attributes or generic unmerging logic. Furthermore, when computing an internal `aria-describedby` (e.g. for an error message), it must be carefully merged with any `aria-describedby` passed down via the `rest` props to ensure both the parent's contextual descriptions and the component's internal error descriptions are announced by screen readers.
**Action:** Always spread `{...rest}` *before* internally computed and critical accessibility attributes. Explicitly merge array-like ARIA attributes like `aria-describedby` using `[rest['aria-describedby'], computedId].filter(Boolean).join(' ') || undefined` to ensure all descriptions are preserved.
